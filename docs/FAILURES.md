## 详细记录

### 1. 登录奖励弹窗
- **现象**：`ep-cplus4` 起跑后停在 LOGIN BONUS 画面，无日志。
- **根因**：`auto_produce` 的弹窗识别不含登录奖励。
- **处置**：手动点掉。
- **教训**：起跑前应先 `cap_game` 看一眼，别假设在主页。

### 2. 卡片详情浮层死循环
- **现象**：
  ```
  030 name-pick SEECT (39.0) at (123,1008)
  031 confirm card at (123,1008)
  032 name-pick  (39.0) at (123,1008)
  ```
- **根因**：点手牌弹出详情层，再点同一坐标只是开关浮层；牌永远打不出去。且浮层左下角 "SELECT" 被 OCR 当成卡名。
- **修复**：`LessonPlayGuard` + `clean_card_name()`（`11de082`）。
- **教训**：**UI 交互是状态机，同一个坐标在不同状态下语义不同。**

### 3. 育成目标面板误开
- **现象**：`[story] tap` 之后一直点灰底，无进展。
- **根因**：点击落在左上角 HUD 区域，打开了「育成目标」面板。
- **修复**：面板检测 + 点底部 X 关闭（`c8ad45c`）。

### 4. 结算误触发连拍
- **现象**：`ep-cplus6` 30 分钟超时，`data/auto/` 里堆了 `final_ep-cplus6_001~159`。
- **根因**：考试介绍页的「合格条件」命中了 `final_phase` 关键词，且 `final_phase` 一旦为真每步连拍 2 张、永不退出。
- **修复**：双条件（评价字母 + 3 位分数）+ 连拍上限 6（`c8ad45c`）。
- **教训**：**任何"进入某模式"的判定都必须有退出条件。**

### 5. clean_lesson_state 集成崩溃
- **现象**：`ep-cplus8` 跑 2 步即 `AttributeError`。
- **根因**：`fix-card-popup` 把它当 `ProduceDriver` 方法调，实际是模块级函数。pytest 只覆盖 `src/`+`tests/`，`scripts/` 接线错误测不到。
- **修复**：改成模块级调用（`da464d0`）+ 新增 `tests/test_auto_produce_wiring.py` 用 AST 静态检查 `driver.xxx()` 是否真实存在。
- **教训**：**脚本层要静态检查，不能只靠 pytest 跑不到的地方。**

### 6. 0 体力进课程
- **现象**：
  ```
  102 [training] SKIP 结束回合（剩下的牌不值得体力）
  110 [training] SKIP 结束回合（剩下的牌不值得体力）
  ```
- **根因**：行动选择只看 `prefer_lesson`/`lesson_every`，不看体力。
- **修复**：体力门（`067bbe4`）：<8 只休息，8-11 不进课，≥12 才允许；课程中体力 < 最低手牌费直接 SKIP。

### 7. SKIP 坐标错
- **现象**：`ep-cplus10` 25 分钟超时；画面卡在体力 0 的课程，回合数不变。
- **根因**：`SKIP_POINT = (660, 868)`，实际按钮在 **(657, 800)**——低 68 像素，每次都点空。
- **修复**：`914761d`。
- **教训**：**坐标必须用真实截图核对，不能凭一次成功就固定。**

### 8. 回合结束确认框
- **现象**：SKIP 点中后画面停在「尚可使用技能卡 确定要结束回合吗？」。
- **根因**：SKIP 会弹确认框，bot 不知道要点「是」。
- **修复**：识别「回合结束 + 确定」→ 点 (500,1200)（`5ccc1c9`）。

### 9. 窗口被最小化（最隐蔽）
- **现象**：所有点击"成功"但画面不动；日志 `[capture] game window is minimized`。
- **根因**：游戏窗口在跑局过程中被最小化（疑似 DMM 抢焦点或 SetForegroundWindow 副作用），点击全部落到不存在的地方。
- **现状**：只在截图失败时补救，**太晚**（点击已空转 12 次）。
- **待修**：每步前置检查 `IsIconic` + 尺寸，异常先恢复再决策。

### 10. 截图 1281 行
- **现象**：`RuntimeError: invalid screenshot shape=(1281, 720, 3)`。
- **根因**：把窗口改成 720x1280 后，540x960 缩放取整多出 1 行。
- **修复**：`_normalize_rows()` 把 1279/1281 统一成 1280。
- **教训**：**不要改窗口尺寸**；540×960 是正确值，内部会自动缩放。

### 11. 暂停门自触发
- **现象**：日志连续 `[pause] 用户正在操作`。
- **根因**：bot 的 `SendMessageWithCursorPos` 也会刷新 `GetLastInputInfo`，下一步误判"用户在操作"。
- **现状**：`b681542` 加了 0.6s 自身窗口 + 30s 强制继续，**但真机日志里仍出现**，需要再查（怀疑 `click_force` 被缓存成局部引用）。

### 12. 分数 OCR 失败选 0 分卡
- **现象**：
  ```
  [training] name-pick 表现的基础 (0.0) at (142, 1008)
  ```
- **根因**：分数宝石读不到 → `score=0` → 被当便宜填充牌，跳过了旁边 27 分的卡。
- **修复**：卡表兜底 + 估值降权 0.9（`d9139a8`）。

### 13. SSR 被低估
- **现象**：奖励界面有 SSR 和闪黄光推荐，bot 选了普通卡。
- **根因**：估值规则里纯 buff 卡 14-15，**SSR 白值卡只有 6.0**（`9/3 + 3`）。
- **现状**：`fix-ssr-value` 正在改为"按效果定档 + SSR +5"。

### 14. 模拟器高估 2 倍
- **现象**：模拟预测 B+/评价点 7653，真机实测 **C/4135**。
- **根因**：`lesson_gain_ratio=1.0`（机制正确），但模拟器牌组的课程得分约 245，真机只有 90-120——牌组强 2 倍，总分就被放大 2 倍。
- **校准**：`ratio=0.5` 时模拟三维 1108 / 评价点 4097，与真机 4135 **误差 0.9%**。
- **教训**：**机制正确 ≠ 数值标定正确。系数必须用真机数据反推。**

## 跨条目的教训（比单条更重要）

1. **单测全绿 ≠ 真机可用**。今天 7 个"已修复"里，3 个真机确认生效、2 个确认失效、2 个未验证。失效的全是"UI 交互契约"类——构造数据测不出来。
2. **要用真实截图做 golden 测试**，而不是 `LessonCard(...)` 手搓。
3. **每个"进入模式"都要有退出条件**（结算连拍、浮层、面板、暂停门都是这类）。
4. **坐标/尺寸这类外部契约，必须每局前置校验**（窗口是否最小化、尺寸是否变化）。
5. **模拟器的数字必须能被真机解释**。对不上时不改结论，改系数。

### 15. 结算页 `[scenario] regular` 循环
- **现象**（`ep-cplus13`，58 步 / 10.6 分钟）：
  ```
  045 [scenario] regular
  ...
  055 同一屏/动作 scenario/regular 连续 12 次（文本微变），停止
  ```
- **根因**：培育结束后的结算/剧情选择画面被识别成 `scenario` 分支，每次点击同一位置但画面只在文本上微变（`changed_rate=0.849`），12 次后触发停机保护。
- **待修**：识别结算画面的真实按钮（下一步/确认/回忆照片选择），而不是走通用 `scenario` 点击。
- **教训**：`scenario` 这类"兜底分支"最容易变成死循环，应当有"同屏 N 次就换策略"的降级。

## 16-26（2026-11-15 晚，真机一轮跑局里暴露并修掉）

### 16. 「再挑战确认」弹窗空点停机
- **现象**（ep-sup1 step 179-188）：考试不合格 → bot 点了「再挑战」→ 弹出「再挑战确认（消耗再挑战道具，重新挑战考试吗？）」，
  然后每步 [dialog] end-produce，10 次停机；画面不动。
- **根因**：第二段确认框只有 取消/确定，没有「再挑战」按钮；旧分支 find_button(再挑战) 找不到 → 落到 end-produce 的 (355,1148) 空点。
- **修复**：6405b46 —— 识别到 再挑战 + 确定/取消 时点确定（消耗票据重打），日志 [dialog] retry-confirm。
- **教训**：同一业务的两段确认框按钮文案不同（再挑战 → 确定），按文案找不到时要看完整布局，不能落到通用兜底点击。

### 17. 考试/试镜里 SKIP 白送回合
- **现象**（ep-sup1）：期中考试 4th/228Pt（1st=597）直接不合格；日志 146/164 [training] SKIP ...、同屏 5 步强制 SKIP。
- **根因**：试镜页和课程页布局相似，被当课程打；体力门、同屏兜底、策略「剩下的牌不值得体力」三个 SKIP 出口在考试里全生效。考试里 SKIP = 一分不得。
- **修复**：45b2e69 —— 顶部 1st..6th 排名条 ROI 识别 → exam_mode：禁三个 SKIP、禁用 audition 布局读数值、每回合硬打一张；日志 [exam-mode]。
- **教训**：**同一个 UI 组件在不同场景的语义不同**（课程 SKIP 合理，考试 SKIP 等于放弃）；进入特殊场景必须显式切换策略，不能复用默认规则。

## 27-30（2026-11-21 T1 真机跑局：从主页起跑到第 3 周，暴露并修掉）

### 27. 主页点「プロデュース」连点 60 步不动（点击落空，TROUBLESHOOTING 2.1 复发变种）
- **现象**（ep-t1-a/ep-t1-b）：bot 从主页起跑，日志每步 `[home] enter-produce` / `[result-tap] gain`，
  `changed_rate=1.0`（呼吸动画），60+ 步画面停在主页；`click` 返回成功。
  但同一坐标用**真实鼠标**（`data/_click_probe.py raw`）点一下立刻进难度页；
  其它屏（难度/偶像/支援卡）用消息点击又能推进——非常迷惑。
- **根因**：`Win32Device.click` 把 720x1280 设计坐标**预缩放**成客户区像素（7e58b4b），
  而 MaaFramework `post_click` 的入参本身就是 720x1280 截图坐标系、原生内部再换算一次
  → **双重缩放**，实际点击落在设计坐标 ×0.75 处。主页「プロデュース(359,1006)」
  ×0.75 ≈ (269,754) 落在角色立绘上，点了等于没点。
  判定方法：`_cursor_probe.py` 观察 `post_click(360,1090)` 后真实光标落在客户区
  `(270,819)`（=360*0.75），证明原生已在缩放，设备层不能再缩。
- **修复**：撤销设备层预缩放（`device.click` 原样传设计坐标）；`click_raw`（自算屏幕坐标
  的真实鼠标路径）保留缩放。回归测试 `tests/test_device_click_coords.py`。
- **教训**：**坐标空间有四层（识别/截图/客户区/屏幕），每层只应由一层代码缩放**。
  排查时先用一个「点一下必然有反应」的观察器（真实光标位置/raw 点击）确认是哪层错了，
  不要看到「点击全部落空」就直接加缩放补丁。

### 28. 难度页「レギュラー」点在两个按钮中间
- **现象**：`REGULAR_DIFFICULTY=(359,900)`，难度选择页 `_scenario_step` 每次点这里，
  画面只在文本上微变 → 5 次后降级、10 次后 `[stuck]`。
- **根因**：真机截图里「レギュラー」按钮中心是 `(220,915)`，`(359,900)` 正好落在
  「レギュラー」与「プロ」两个胶囊按钮之间的缝隙（白边交界）。
- **修复**：`REGULAR_DIFFICULTY = (220, 915)`（2026-11-21 实测点下去直接进编成流程）。
- **教训**：固定坐标必须**用当次真机截图量按钮中心**，不能落在「看起来差不多」的边界上。

### 29. 「自动编成」确认框被误判成培育记录页
- **现象**（ep-t1-c）：支援卡编成页点「自动」弹出确认框（将自动编成支援卡 / ※当前编成未保存 /
  取消 / 确定），随后 12 步 `[record] close`，点 (360,1197) 空转停机。
- **根因**：`is_record_screen` 用「编成支援卡」子串判培育记录页，而被确认框文案
  「将自动编成支援卡」命中；记录页分支的关闭点 (360,1197) 又正好落在取消/确定之间。
- **修复**：`is_record_screen` 先排除「自动编成 / 当前编成未保存」；回归测试加进
  `tests/test_produce_ui.py::test_settlement_keywords_recognised`。
- **教训**：用**子串**做屏分类时，要检查反过来被更长短语包含的情况（编成支援卡 ⊂ 自动编成支援卡）。

### 30. 通信错误弹窗（获取资产失败 E203）被加载帧快速路径盖住
- **现象**（ep-t1-d）：第 3 周附近游戏弹出「通信错误 / 获取资产失败 / 重试 / 返回标题」；
  bot 连续 200+ 步 `[loading] wait`，0.9s/步烧完 300 步预算退出（`done=false`），
  一局报废。
- **根因**：错误弹窗盖在加载帧上，`produce_loading` 模板仍然命中 → 走加载快速路径、
  **整屏 OCR 被跳过**，永远读不到「通信错误/重试」；而 `decide` 的 loading 分支又含
  「通信」关键字，即便读到也会先判成 loading。
- **修复**：① `decide` 在 loading 之前加 `net-error` 分支：命中「通信错误/获取资产失败/
  重试+返回标题」→ 点「重试」（OCR 行中心，兜底 `NET_RETRY=(510,1151)`）；
  ② `auto_produce` 加载快速路径连续 12 步强制完整 OCR 一次（`LOADING_FAST_OCR_EVERY`）。
  回归测试：`test_net_error_dialog_clicks_retry_before_loading` 等 3 条。
- **教训**：**快速路径（模板/缓存）必须有「定时回看全量」的逃生门**；否则一个新弹窗
  就能让 bot 在快速路径里空转到超时。网络错误弹窗不是「loading」，要当成可恢复状态重试。

### 31. 训练里「无可用决策，点击中位卡兜底」无限空转（手牌读不到/已空）
- **现象**（ep-t1-k）：训练帧连续多步 `[training] 无可用决策，点击中位卡兜底`，
  同屏 5 步强制 SKIP 也推不动，最后 `手牌0` 判死退出。
- **根因**：`decide_lesson_pick` 返回空（手牌 OCR 为空/全被剔除）时，`auto_produce`
  只会点屏幕中央兜底——既不会读新牌，也不结束回合，纯空转。
- **修复**：连续 2 步无决策时（课程模式）直接点 `SKIP` 结束回合并清 `same_screen`；
  考试模式仍不 SKIP（点中央推进），但日志带 `eng=…` 可看出来。
- **教训**：兜底动作必须有**状态转移**（结束回合/重读），不能是"再点一次同一个空位置"。

### 32. 暂停帧被算进「同屏卡死」，[pause] 直接滑到 [stuck] 退出
- **现象**（ep-t1-l）：连续 8 步 `[pause] 用户正在操作，暂停出牌` 后立刻
  `[stuck] 同一屏连续 10 步无变化…SKIP 也推不动，退出本局`（45 秒结束）。
- **根因**：`same_screen.observe()` 在暂停判断**之前**执行；暂停期间画面本来就不变，
  同屏计数照样累计 → 暂停等于给卡死判据喂数据。
- **修复**：`result` 以 `[pause]` 开头时 `same_screen.reset()`（暂停帧不参与同屏判死）。
- **教训**：同一帧里「不动作」的原因（暂停/等待/加载）必须先于死循环判据排除，
  否则两种保护机制会互相触发。

### 39. 设计错误：搜索因"读不到价值"建议 SKIP，被直接执行 → 整局大面积跳课
- **现象**（ep-finish7，C/4242 的直接原因）：课程里大量 `lesson-skip`；考试里 9/32 步
  `eng=expectimax fallback=搜索未产出动作，退回规则`，实际是 expectimax 算出 SKIP（牌分读到 0）
  而考试禁 SKIP → 退回规则。
- **根因**：搜索/规则的 SKIP 语义是"打牌不如不打"，但**读不到分数不等于 0 分**（buff 牌本来就没分数，
  靠卡表效果估值）。把"未知"当"0"直接跳 = 白丢回合属性，整局属性崩 → 期中不合格。
- **用户规则（2026-11-21 定死）**：**只有"所有牌都付不起（真没体力）"才允许 SKIP**；其他任何原因
  （读不到分、分低、搜索建议）都不许跳过。读不到价值只说明 OCR/卡表有问题，去修那个，不许用 SKIP 补偿。
- **修复**：`_decide_rules` 删掉全部"价值型 SKIP"；`expectimax/beam/uinet` 返回 SKIP 一律拦截改打；
  `unknown_score_fallback=skip` 配置废除（写 skip 也按 cheapest）；考试禁 SKIP 不变。回归测试全部改写绑定该规则。
- **教训**：**策略里的"放弃动作"只能是物理不可能，不能是模型不确定**。不确定就退到保守可行动作，
  并把不确定性写进日志/指标，而不是用它当跳过理由。

### 40. 设计错误：搜索失败静默退回 rules → 用户规则「bot 不许回退 rules」
- **现象**（C/4242 那局）：考试 32 步里 9 步 `eng=expectimax fallback=搜索未产出动作，退回规则`；
  日志里 `eng=expectimax` 看着像搜索在打，实际这一手是规则引擎选的，事后才能从 `fallback=` 发现。
- **根因**：`LessonPolicy.decide` 先无条件算一遍 `rules_action`，搜索引擎返回 `None`（异常 / 状态没读全 /
  搜索建议 SKIP / 结果失配）就整手改用规则；beam 缺全知退回回合内搜索是允许的，但 uinet→rules、
  SKIP 被拦截→rules_action 等也都在用规则兜底。等于"降级"发生在暗处。
- **用户规则（2026-11-21 追加）**：**bot 不许回退 rules**。搜索失败 = bug（OCR/卡表/参数），
  要暴露出来去修，不许用规则引擎或跳过补偿。
- **修复**：
  - 搜索引擎（expectimax/beam/uinet）**不再调用 `_decide_rules`**，任何失败都不拿 rules 兜底：
    搜索建议 SKIP 但还有付得起的牌 → 按搜索自己的动作排序硬打（expectimax `actions` /
    beam 根回合计划首牌 / UINet 合法动作概率）；状态没读全 → `wait` 等下一帧重读；
    搜索异常 / 结果失配 → 抛 `RuleFallbackBlocked`；
  - `auto_produce` 捕获后写 `[engine][BLOCKED]` + `fallback= rule-fallback-blocked` 并中止本局；
  - 入口 `--engine`/`produce.engine` 非法 → exit 2；显式 `engine=` 写错 → 构造期 `ValueError`；
  - bot 入口默认引擎改为 `expectimax`；`--engine rules` 只保留给 A/B 对照/离线复现（日志会警告）。
- **测试**：expectimax/beam/uinet 的「异常退回 rules」用例全部改写为「必须 blocked」；新增
  skip→按搜索排名硬打、beam 根计划首牌、uinet 概率硬打、wait 语义、显式 engine 写错等回归。
- **教训**：**降级必须是显式的、可观测的失败，不能是静默换引擎**——否则日志里的 `eng=` 会撒谎，
  事后根本分不清"这手是谁决定的"。宁可中止本局，也不要一个悄悄变弱的 bot。

### 42. 舞蹈课程连续打 buff 牌 → 0 分 FAILED（用户现场看到）✅ 2026-11-22 已修
- **现象**（ep-t3-3 step269–290 / ep-t3-4 step1–3，两个进程重叠同一屏）：舞蹈课程每回合都
  `name-pick` 选 buff 牌（表现的基础 / 大声应援 / 表情的基础），课程 `lesson_score=90`、**FAILED**；
  用户观察："训练舞蹈时一直选 buff 牌，一分没得，failed 了"。
- **根因（两层，都是"模型以为"和屏幕实际不一致）**：
  1. **课程 HUD 语义读错**：右上角是**培育属性值**（不是课程分）；正中圆环「CLEAR截止 / PERFECT截止 N」
     是**还差 N 分**（过了 CLEAR 换成 PERFECT）。旧读法把属性值当课程分、把还差分当过关线：
     真机帧「属性 90 / CLEAR截止 30」被当成"分数 90 ≥ 过关线 30 → 已 PERFECT"，
     档位效用全部封顶 2.00 → expectimax 每回合建议 SKIP → 禁跳规则按动作排序硬打 →
     排序挑中 buff 牌（buff 不给课程分）→ 整节课 0 分。
  2. **每回合出牌上限写死 3**：游戏**默认每回合只能出 1 张牌**（一手 3 张是"选 1 张"；
     额外出牌次数来自卡效果 `ExamPlayableValueAdd` / P 道具）。证据：四场采集考试共 39 个
     实战回合，32 回合正好 1 张、7 回合 2 张（2 张的都是卡效果给的额外出牌）；
     课程实拍"打 1 张 → 回合数 -1"；社区/维基口径一致。旧搜索 `play_limit=3`（"手牌 3 张"的误读）
     让"buff + 两刀"在模型里永远划算 → 每回合先铺 buff → 整节课 0 分。
- **修复**：
  - `vision/lesson.py`：`LessonReader` 读圆环档位（`CLEAR截止`/`PERFECT截止`）+ 按
    "属性值 − 开课属性值"换算课程分；**过关线 = 已得分 + 圆环还差分**；满分线查档位表
    （普通/SP = 2×，追い込み 90→360、165→600）；`LessonState` 新增 `perfect/goal/attr`，
    `score` 语义改为"本课已得分"；`reset_lesson()` 每课重置属性基线（`auto_produce` 在课程开始时调用）。
  - `policy/lesson.py`：`_search_state` 改 `play_limit=1`（每次决策只建模"现在打 1 张"，
    额外出牌时下一帧重新读屏再决策；`plays_used` 不再喂搜索，避免 plays_left=0 假死）；
    满分线用读屏换算值；**硬打保证得分**——搜索建议 SKIP 时先筛"屏幕分数预览 > 0"的牌
    （buff 牌记 0）按（搜索价值, 屏幕分）硬打。
  - `auto_produce.py`：`lesson_score` 记真课程分（0 分也记；旧日志把属性值 90 写成 lesson_score）。
- **测试**：`tests/test_lesson_play_f42.py` 3 条真机帧回放（HUD 换算 / 最后一回合必须选
  魅力的基础 29 而不是 buff / "buff 多、分数少"合成场景）+ HUD 换算 4 条假 OCR 单测 +
  `test_hardplay_prefers_scoring_card_on_flat_tie`（动作全平手时硬打仍要选正分牌）；
  全量 pytest **934 passed / 1 skipped**（935 收集 / 66 文件）。
- **遗留（不属于 #42，已记 WORKPLAN T5/B3）**：`sim/lesson.py` 的 `plays_per_turn` 默认 3
  也要对齐真机规则（默认 1 张 + 额外出牌），模拟器整局 A/B / 评分要重新标定；
  该规则对**考试**同样成立（本修复也改了考试搜索的出牌上限）。
- **教训**：「不许 SKIP」是用户规则，但"硬打"必须是有得分的硬打；跳过会输，乱打 buff 也会输。
  另一个教训：**屏幕上的数字先弄清语义再进模型**——"右上角数字"不是分数、"圆环数字"不是过关线，
  两个误读叠起来比单个 OCR 读错更隐蔽（读得很准，但语义反了）。

## 评估口径约定（2026-11-16 用户指定）

**不再用 C+ 达成率 / B 率这类阈值二元指标评估策略。**

理由：C+ 是初星课题的要求，不是优化目标；二元指标会把分布压成一个数，
看不出"均分涨了但尾部崩了"或"整体挪动但没变形状"。

固定用这五个：

| 指标 | 用途 |
|---|---|
| **评价点 P50** | 主指标 |
| **评价点 P90** | 尾部（打榜看这个）|
| 评价点均值 | 整体水平 |
| 评价点 P10 | 下限（防尾部崩）|
| PERFECT 率 | 课程档位 |

新写的评测脚本（`eval_expectimax.py`、`sim_million.py` 的新版本等）一律按这个口径；
旧脚本里已有的 C+ 率输出不必回改，但**新报告不许再用它当结论**。
