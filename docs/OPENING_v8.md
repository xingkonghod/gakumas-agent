## 3. v8 任务（顺序固定）

### P0 真全锁（先做，收益确定）
1. **失锁不判死 + 后验信念兜底**：非锁定/掉线状态保留 `g.mirrors`（与全部观测一致的后验集）做 PIMC，
   替掉 `ctx.worlds(4)` 随机世界；候选集每回合继续裁剪、继续尝试重锁。
2. **约束只用「干净观测」**：每回合用 `m1_graph.known_info_ok` 判该回合是否全程已刻画，脏回合的抽牌**从扫描约束剔除**
   （不是整局作废）；开局快照永远干净（任何效果之前）。
3. **`rescan_open=2`**：允许 graph-unclean 牌组也走「开局快照重扫」（诊断跑里 `RESCAN(opening)` 从 1.4 万/2.9 万候选
   在 turn 2–3 锁上，已验证有效）。
4. **扫描提前**：turn 1 就用开局快照后台开跑（现在要等 ≥6 张），候选集早准备好。
5. **软核验（soft lock）**：单候选过了手牌跟随、但整屏只有少数「会漂移」字段不一致时，允许软锁 + 逐步校验；
   偏离时退回信念集而不是 `lost`。**先用已就绪的 `_v7dbg` 诊断投稿抓 `lock_diff`**（`data/_v7_dbgread.py`
   读 `lock_diff/lock_seed/lock_hint`），再定白名单（手牌序列 + 牌堆 multiset + turn + legal 必须相等）。
6. **验收**：连续 3 次独立全量 240 的 `lock_mode` 统计 —— **硬失败 0–1 槽/次、假锁 0、软锁残差有界**；
   A 组 35 槽的 8,036,635 缺口应基本回收（预期 +25,000~+33,000 均值）。

### P1 搜索强度升级（打 B 组 + MID）
1. **MID 也上 FINAL 配方**：`portfolio_hi` 应用到全部层（或直接改基础 portfolio 为 s5 倾斜）、
   `max_starts_hi` 提到 24→32（MID 也用）、加 **1M transitions 深臂**（`deep_trans=1000000, deep_waves=1`）。
2. **把每步预算用满**：v7 MID 每步 4.1s/7s、FINAL 5.2–6.2s/7s；cap 绑定 → 抬高 cap + lane 投影准入（已是总墙钟口径）。
3. **用定向 eval 量化**：`--only <out/_v8_low_problems.txt 的 55 题>` → 110 槽 ≈35–40min/轮，逐槽算 ratio。

### P2 逐题预算表（最后 10–15% 缺口）
槽集合是固定的（120 题 × 2 保密种子），可对最差 15–20 题（≈60% 缺口）给专属
`starts / step_trans(1M) / portfolio / pool_threads`，写成 `pid → params` 表进投稿；定向 eval 迭代到 73 槽全 ≥90%。

### 验收（唯一可信判法）
1. 每轮**定向 eval**（55 题 / 110 槽）逐槽 ratio，要求 73 → 0；
2. 同时确认 159 个已达标槽**不退化**（批次里带上或最后全量 240 对比）；
3. 最终一次**全量 240**（单 eval、不带 `--only`、parallel 6、budget 10）出新的官方单行；
4. 目标：**240/240 全部 ≥90%** → 均值 **≥1,547,576**；不再追 1.6M（那是 100% 天花板 1,597,934 的事，不可承诺）。
