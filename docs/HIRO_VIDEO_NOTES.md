```

  培育画面流程用 KAA 的任务 + H.I.F 专用补丁
```

## 三条工程原则（值得抄）

1. **层与层只交换数据契约**
   - 读不到的字段留空，**绝不猜**
2. **状态只由纯函数更新**
   - 同样的观测序列 → 同样的状态 → 任何一局都能离线重放、逐步比对
3. **记账 + 互验**
   - 每个动作前先算「下一步应该读到什么」，再和识别结果对照
   - 明显不合理的读数（掉位、越界、倒退）**丢弃重读**

## 06:23 后的实机演示（第 32 局）

视频后半段是完整一局 H.I.F 考试的第一视角解说，展示了 LLM 在具体牌面上的判断，例如：

- "先攒元気，最后一次性転移"
- "センブリソーダ 这回合先不喝，留着"
- "成長痛 付 5 体力，4 回合后元気 ×2.8"
- "約束 的收益随元気增长，所以先ひなたぼっこ 把元気推到 49"

**关键观察**：它不是纯搜索，而是「**规则 + LLM 在候选里权衡**」，并且解释每一手的理由。

## 对我们的可借鉴点

1. **互验机制**：动作前预算下一帧，对不上就重读 —— 我们没有
2. **纯函数状态**：可以离线重放 —— 我们的 run_record 有雏形但没做到
3. **复盘页自动生成**+人工标注转回归用例 —— 我们完全没做
4. **插件化三处替换** —— 我们是硬编码
5. **Windows 支持还不成熟** —— 这是我们的相对优势（我们就是 Windows）
