# gkagent-ex-seed-v6 —— 预算内自适应波次（准入控制）

**承 v5 全部机制**（自锁种子 + 失锁重扫 + 消费图 graph-clean 门 + 规模自适应起点 + core_tail 精确尾 +
去墙钟扫描等待 + `vote_sec_cap=0.8`），**改的是每步搜索的调度**：把 v5 空转的墙钟换成
**20–30 个不会被 deadline 截断的起点**（v5 固定 12 个、每步只用 2.4s/7s）。

基础 = `gkagent-ex-seed-v5`（copy 后改；v5/v4/v3 等原版零改动，vendor DLL/exe MD5 与 v4 全一致、不重编）。
`needs_gkms=True`、`sees_seed=False`、`about.sees="seed"` 如实声明看牌序。入口 `algo.py:ExSeedV6Algo`。

## 动机（v5 托管 240 局逐步记录实测，`data/_v6_stepscan.py` / `data/_v6_analyze.py`，8,000 步）

- 锁定后每步只用了 **2.4s / 7s**（`search_use`×budget）：6,898 个锁定步合计空转 **35,359s = 2.9×**；
- v5 的 over 全部来自**锁定前候选管线**（12,171 候选时单步 10.5–27s），**不是** pool 波次；
- **v5b（waves=3，18 起点）over 8→57 的机制**：每个起点拿 `deadline=min(剩余,4s)`，队列里第 2 轮起点在
  deadline 计时开始后才开跑 → 单步 18–23s，被截断的搜索白烧（注意 `core_search` 的 status 0 = 无内部失败，
  **撞 deadline 也是 0**，不能拿 status≠0 当截断判据）。⇒ **加起点必须同时做准入控制**。

## v6 改了什么（一条机制，单调安全）

| # | 机制 | 说明 |
|---|---|---|
| ① | **预算内自适应波次**（流水线式发起点） | 去掉「几波」概念：每次发起点前过准入控制 `剩余 ≥ 预期×1.25+0.10`；单次 `deadline=min(4.0, 预期×1.5)`；**预期** = 该 transitions 预算下最近 6 次**完整**搜索的 `prep+elapsed`（中位/最新取大；撞 deadline 的样本 ×1.25 上调） |
| ② | **anytime 预算尾巴** | 剩余不够一个完整起点时，用 `deadline=剩余−0.15` 发短搜 —— 绝不越界（不增 over），结果只取更高终局分 |
| ③ | **每步起点上限** | `max_starts=24`（v5=12）；RoutePool 只采纳更高终局分 ⇒ 仍单调安全 |
| ④ | **v5 逐位复现** | `waves=1, pool_threads=1, portfolio="", partial_tail=0, max_starts=0` = v4/v5 原调度 |

预锁阶段不动（`scan_wait_mode=done` / `vote_sec_cap=0.8` / `rescan_open=1` / `tail_turns=2` 逐位保留）。
